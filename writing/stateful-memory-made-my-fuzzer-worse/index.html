My Stateful Memory Made the Fuzzer Worse

25 Jul 2026 · 3 min read · llm research evaluation

TL;DR
  • One run per arm said memory helped. Ten runs per arm said it hurt (p = 0.0097).
  • Telling a model what to avoid pulls it toward those things. A list of untried cells worked better.
  • Over a six-hour campaign, memory still paid off: covered cells went from 125 to 141.

Since November 2025 I have been building an LLM-driven tester for 5G protocols. The model reads the specs, proposes odd message sequences, and a real testbed runs them. I’ll write about the whole thing properly later. This post is about one small piece, because it taught me something I keep seeing elsewhere.

The piece is memory. A fuzzer that forgets what it already tried will keep trying the same things. So I gave the generator a memory: a short list of the test cells it had already covered, and an instruction to avoid them.

The pilot looked great

I ran one campaign with memory and one without. Duplicate tests dropped from 50% to 33%. The number of distinct behaviours I found went from 12 to 16. I was ready to write the paragraph.

Then I ran it properly: ten campaigns per arm, a rank test, an effect size. The result flipped. With memory, the median number of distinct behaviours fell from 15 to 12.5 (p = 0.0097). The first result was noise, and I had nearly built on it.

Why it hurt

I spent a while reading about this and the answer is not exotic. If you write “do not do X, Y, Z” in a prompt, you have put X, Y and Z in the prompt. Models drift toward what is in front of them. My list also grew every round, so the context got longer and the model repeated itself more.

The fix was to stop describing the past and describe the frontier instead: a short “here are the cells you have not tried yet” list, placed at the end of the prompt. It carried the same information as the old list.

What I can claim

On the improved setup, memory was statistically neutral on every metric I tracked. The no-memory baseline was already producing almost no duplicates, so there was little left to remove.

Where it did help was over a long run. In a six-hour campaign that carried the frontier forward, covered cells went from 125 to 141, and the tracker grew from 633 to 1,070 tests. So memory pays off across a campaign, not within a single run, and I’d be wrong to sell it as more than that.

What I took from it

  • One run per arm told me the opposite of what ten did. Run ten.
  • Tell the model where to go.
  • Write down the neutral result too. It stopped me from building the next experiment on a result that wasn’t there.
Caveat
Ten campaigns per arm is better than one, but still small. I report the rank-test p-value and an effect size. A neutral result on the improved setup means no detectable difference.
